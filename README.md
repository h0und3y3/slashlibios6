# Slashlib iOS 6 — Objective-C port

Цель проекта — перенести функции `Slashlib-iOS10` на Objective-C и UIKit, совместимые с iOS 6 / ARMv7. Swift-код не компилируется под iOS 6: здесь используются ручное управление памятью, `NSURLConnection`, `NSJSONSerialization`, `NSUserDefaults` и старые компоненты UIKit.

## Что перенесено в этой ревизии

- Пять вкладок: Главная, Поиск, Избранное, Закладки, Аккаунт.
- Главная: продолжение последнего чтения, случайная подборка и подборки по случайным жанрам.
- Поиск SlashLib; MangaLib можно включить в настройках. Есть постраничная подгрузка результатов.
- Карточка тайтла, запрос описания и списка глав, сортировка глав.
- Читалка: вертикальная лента, постраничный режим, направление справа налево, сохранение и восстановление позиции.
- Сжатое декодирование изображений через ImageIO и ограничение одновременной загрузки для экономии памяти.
- Выбор фона страниц, светлая/тёмная/автоматическая тема, keep-awake и энергосбережение.
- Избранное, история/последняя позиция чтения, прочитанные главы и отдельные ручные закладки в `NSUserDefaults`.
- Загрузка глав в `Documents/SlashlibOffline`; скачанные страницы открываются без сети.
- Вход в lib.social через Bearer-токен с хранением в Keychain и проверкой `/auth/me`.
- GitHub Gist: поиск или создание приватного Gist, двустороннее слияние избранного/закладок/истории, объединение прочитанных глав и tombstones для удалений.
- Иконки для старых iPhone/iPad, конфигурация ARMv7 и упаковка одной `.app` в `.ipa` и `.deb`.

## Что ещё не является полной копией оригинала

Остаются функции, которые ещё требуют переноса/проверки:

- авторизация непосредственно в аккаунте lib.social и управление сессией сайта;
- домашние случайные подборки по жанрам, теги и фильтры каталога;
- полный набор настроек оригинала (цвет акцента, анимации, автоскрытие панелей, профили телефона/планшета);
- зум и продвинутая обработка длинных страниц полосами, расширенное управление очередью загрузок и отмена;
- диагностика и восстановление после аварийного завершения;
- проверка всех API/CDN-эндпоинтов на реальном устройстве iOS 6.

Это функциональный перенос в работе, не подтверждённая 1:1 копия. Исходный README помечает некоторые API-поля и хосты изображений как непроверенные. Кроме того, старый TLS-стек iOS 6 может не установить соединение с современными серверами даже при корректном коде.

## Сборка

GitHub Actions может запускать сборку, но для iOS 6 / ARMv7 нужен macOS runner с установленным старым Apple toolchain, который ещё умеет собирать ARMv7 и выставлять `IPHONEOS_DEPLOYMENT_TARGET=6.0`. Обычные GitHub-hosted runners с современным Xcode, как правило, не содержат нужный ARMv7 SDK/toolchain.

В workflow выбран self-hosted runner с labels `self-hosted`, `macOS`, `ios6`:

1. Добавьте совместимый Mac в GitHub: Settings → Actions → Runners.
2. Назначьте ему label `ios6`.
3. Установите Xcode/SDK с поддержкой ARMv7 и `dpkg-deb`.
4. Отправьте проект в ветку `main` или запустите workflow вручную.
5. В Actions → Artifacts появятся оба файла.

Локальная сборка на настроенном Mac:

```sh
xcodebuild -project Slashlib.xcodeproj -scheme Slashlib -configuration Release -sdk iphoneos \
  ARCHS=armv7 VALID_ARCHS=armv7 IPHONEOS_DEPLOYMENT_TARGET=6.0 \
  CODE_SIGNING_REQUIRED=NO CODE_SIGNING_ALLOWED=NO \
  CONFIGURATION_BUILD_DIR="$PWD/build" clean build
./package-ipa.sh
./package-deb.sh
```

`build/Slashlib.ipa` создаётся неподписанным. Для установки на обычное устройство нужна подходящая подпись; `.deb` предназначен для jailbreak-устройств. Успешная сборка и запуск на физическом устройстве в этой среде не проверялись.

## Структура

- `Sources/` — Objective-C интерфейс, API, хранилище, загрузки и Gist sync.
- `Resources/` — Info.plist, иконки и control для Debian.
- `.github/workflows/build.yml` — сборка и публикация `.ipa` + `.deb` как Actions artifacts.
